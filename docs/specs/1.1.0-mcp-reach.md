# Spec: 1.1.0 — easy setup in every local MCP client

Status: approved by Talati on 2026-11-01 (phase 1 of the MCP client-readiness plan).
Owner: Karen (PM). Release: 1.1.0.

## Goal

Make No2SQL a one-step install in every AI tool that runs local MCP servers, and
list it where people discover MCP servers, so more people use it.

## Decisions

- Phase 1 only. Remote mode (HTTP transport, auth, Docker) is phase 2 and is not in 1.1.0.
- Local only. No hosted No2SQL service.
- Two install paths, both supported:
  - **No .NET needed:** download a per-platform zip from GitHub Releases.
  - **.NET 10 SDK users:** `dnx No2SQL@<version> --yes`.
- Publishing to NuGet, GitHub Releases and the official MCP Registry is approved.
- Dev PRs do not change the version. Karen bumps to 1.1.0 in this spec/release PR, which merges last.

## Out of scope

- HTTP / Streamable HTTP transport, authentication, Docker (phase 2).
- New or changed tool behaviour (SQL, ERD, relationship inference).
- Code signing and macOS notarization (follow-up if users report Gatekeeper trouble).

## Work items

Each item is its own branch (`<name>/<area>`) and PR. Violet tests and Mark reviews every PR.
Devs send Violet the PR link when it is ready.

### MCP-1 — make the package runnable with `dnx` (Ayush, branch `ayush/dnx-package`)

Acceptance criteria:
1. `dotnet pack` produces a NuGet tool package of type `McpServer` (`PackAsTool=true`,
   `PackageType=McpServer`) plus the RID-specific packages .NET 10 needs, for at least
   win-x64, linux-x64, osx-arm64, osx-x64, linux-arm64, win-arm64.
2. With the .NET 10 SDK and the packed output as a local source,
   `dnx No2SQL@<version> --yes --source <dir>` starts the server and answers an MCP
   `initialize` + `tools/list` over stdio with all 10 tools. (`--source`, not `--add-source`:
   until 1.1.0 is on nuget.org, the existing non-tool 1.0.3 there wins resolution.)
3. The packages are self-contained: the runtime is not needed beyond what `dnx` itself needs.
4. `.mcp/server.json` still ships inside the package, and its `packages[0]`
   (`registryType: nuget`, `transport: stdio`) matches how the package is launched.
5. There is one packaging source of truth: either `No2SQL.nuspec` is removed or the PR
   explains why it stays. CI's pack and no-pdb steps still pass.
6. The `PackAsTool=false` comment in the csproj is replaced with the reason for the new setup.
7. `initialize` reports `serverInfo.version` equal to `PackageVersion` (today it reports 1.0.0.0
   because the assembly version is not set). Found by Violet in MCP-7.

### MCP-2 — per-platform zips on GitHub Releases (Dan, branch `dan/release-zips`)

Acceptance criteria:
1. A workflow triggered by pushing a `v*` tag (and by `workflow_dispatch`) publishes the
   self-contained single-file exe for each of the 6 RIDs above and attaches
   `No2SQL-<version>-<rid>.zip` to a GitHub Release for that tag.
2. Linux and macOS binaries are executable when unzipped (mode set inside the zip).
3. A `SHA256SUMS.txt` file is attached next to the zips.
4. The workflow does not push to NuGet and does not need any secret other than `GITHUB_TOKEN`.
5. Running it on a test tag in a fork or via `workflow_dispatch` dry run is shown in the PR.

### MCP-3 — tool annotations and descriptions (Joel, branch `joel/tool-annotations`)

Acceptance criteria:
1. Every tool in `No2SQL/Tools/SchemaTools.cs` sets `Title`, `ReadOnly = true`,
   `Destructive = false`, `Idempotent = true`, and `OpenWorld = false`.
2. Every tool description says what it returns and when to use it, in one or two sentences.
   Every parameter has a description, including allowed values (`auto|mongo|sql`).
3. `tools/list` output shows the annotations (screenshot or JSON in the PR).
4. No change to tool names, parameters or behaviour.

### MCP-4 — complete `server.json` metadata (Dan, branch `dan/server-json`)

Acceptance criteria:
1. `NO2SQL_MONGO` is marked `isRequired: true` and `isSecret: true`.
2. `NO2SQL_ALLOWED_DATABASES` and `NO2SQL_BLOCK_SYSTEM_DATABASES` are declared as optional
   env vars with descriptions and defaults.
3. The file validates against its `$schema` (validator output in the PR).
4. The version fields are left at 1.0.3; Karen bumps them in the release PR.

## Security bar (Mark, review on PR #38)

Every phase 1 PR is reviewed against these, in addition to its acceptance criteria.

- **MCP-2 release workflow:** top-level `permissions: contents: read`, `contents: write` only on the
  release job; trigger only on `v*` tags and `workflow_dispatch`, never `pull_request_target`;
  third-party actions pinned to a full commit SHA with a version comment; build from the tagged
  commit and fail if the tag does not match `PackageVersion`; generate `SHA256SUMS.txt` in the same
  job and run `sha256sum -c` before upload (build provenance attestation encouraged); no
  `curl | sh`, no unpinned downloads, no `${{ github.event.* }}` interpolated into `run:` (pass via
  `env:`); zips hold only the exe, LICENSE, NOTICE and TRADEMARK.md; keep the no-pdb check.
- **MCP-1 dnx packaging:** `EnablePackageValidation` on, deterministic CI builds
  (`ContinuousIntegrationBuild=true`); if the nuspec goes, the package still excludes real
  `appsettings.json` values and still includes NOTICE and TRADEMARK.md.
- **MCP-4 server.json:** `NO2SQL_MONGO` description says it is a credentialed connection string;
  guardrail vars documented with defaults and an allow-list recommendation; no
  `packageArguments` that take paths or connection strings.
- **MCP-3 annotations:** must stay truthful; any future write or network side effect changes them.
- **MCP-5 README:** connection string always in the client's env config, never on the command
  line; examples recommend `NO2SQL_ALLOWED_DATABASES`; quarantine note targets the one downloaded
  file, never a Gatekeeper-wide disable.
- **MCP-7 smoke test:** assert no crash and no environment leak in `initialize` or errors.
- **MCP-6 publishing:** before 1.1.0 is pushed, Talati turns on 2FA on the nuget.org account and
  requests package ID prefix reservation for `No2SQL`. The NuGet API key stays with Talati, scoped
  to push `No2SQL` only, and is not added as a repo secret.
