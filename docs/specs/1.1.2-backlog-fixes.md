# Spec: 1.1.2 — backlog fixes

Status: requested by Talati on 2026-11-23 ("let's do backlog fixes").
Owner: Karen (PM). Release: 1.1.2 (patch: fixes only, no new tools).

## Goal

Fix the five issues found while shipping 1.1.0 and 1.1.1, so that No2SQL behaves well when
it is misconfigured and AI clients can tell when a tool failed.

## Out of scope

- Remote mode (HTTP transport, auth, Docker) — phase 2.
- New tools or changes to SQL / ERD output.

## Work items

Each item is its own branch and PR. Mark reviews and Violet tests every PR, and nothing merges
without Talati's "merge" (see the merge checklist). Dev PRs do not change the version.

### BL-1 — start and answer without a connection string (Ayush, `ayush/no-conn-startup`)

Today `SchemaAnalyzer` throws in DI when `NO2SQL_MONGO` is unset, so every tool fails,
including `test_connectivity`.

1. With `NO2SQL_MONGO` unset, the server starts, `test_connectivity` succeeds, and
   `tools/list` still lists all 10 tools.
2. Every tool that needs MongoDB returns one clear message naming `NO2SQL_MONGO` as missing
   (no stack trace, no connection string echoed).
3. With `NO2SQL_MONGO` set, behaviour is unchanged.
4. Includes **BL-4**: remove the `ConnectionStrings:MongoDb` / `appsettings.json` fallback in
   `Program.cs` (it is never copied to the output, so it never worked for zip or `dnx` users).
   `NO2SQL_MONGO` is the only config source. Remove or update any README line that mentions
   the appsettings option.

### BL-3 — hide blocked system databases in `list_databases` (Dan, `dan/list-db-filter`)

1. When `NO2SQL_BLOCK_SYSTEM_DATABASES` is true (the default), `list_databases` omits
   `admin`, `config` and `local` (case-insensitive, same set as `McpGuardrails`).
2. When it is false, they are listed as today.
3. The `NO2SQL_ALLOWED_DATABASES` allow-list still applies as today.
4. Reuse the guardrail's blocked set; do not duplicate the list.

### BL-2 — report tool failures as MCP errors (Dan, `dan/tool-errors`, after BL-1 merges)

Today a failing tool returns `isError: false` with the error text as a normal result.

1. Every failure path in `SchemaTools` (exceptions, guardrail rejections, the
   "SQL ERD failed" branches, BL-1's missing-connection message) returns a `tools/call`
   result with `isError: true` and the same human-readable message.
2. Successful calls are unchanged (`isError` false or absent).
3. Messages keep today's rule: error id and a short reason, no stack traces or secrets.

### BL-5 — CI gate for registry metadata (Violet, `violet/server-json-gate`)

1. `prepublish-gates.yml` validates `No2SQL/.mcp/server.json` against the schema named in
   its own `$schema` and fails on any error.
2. It fails unless both `README.md` and `No2SQL/README.md` contain
   `mcp-name: <server.json name>` exactly.
3. Extend the MCP smoke test: a tool call that must fail (for example `list_databases`
   with no `NO2SQL_MONGO`) returns `isError: true`. Enable that check once BL-2 merges.

### Docs pass (Joel, `joel/readme-1.1.2`, after BL-1 and BL-2 merge)

1. README and package README describe the new behaviour: the server starts and
   `test_connectivity` works without `NO2SQL_MONGO`; Mongo tools return an error naming it.
2. No remaining mention of `appsettings.json` as a config option.
3. Tool descriptions in `SchemaTools.cs` stay accurate (for example `test_connectivity`).

## Release (Karen)

Release PR merges last: bump 1.1.1 → 1.1.2 in the csproj, both `server.json` fields,
`MAIN_PKG` / `RID_PKG` in `prepublish-gates.yml` and README references, plus a
`CHANGELOG.md` entry. Then Talati tags `v1.1.2`, pushes the seven packages from the `main`
run's `no2sql-packages` artifact (platform packages first), and runs `mcp-publisher publish`.
