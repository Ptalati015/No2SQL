# Spec: P2-6, hardening middleware for HTTP mode

Author: Mark (security). Date: 2026-11-25. Implements: Dan (`dan/http-hardening`, after P2-3).
Parent spec: `docs/specs/1.2.0-remote-mode.md` (PR #57). Companion: `docs/security/1.2.0-p2-5-threat-model.md`.

## 1. What the SDK already does, and what it does not

Checked against `ModelContextProtocol.AspNetCore` **2.4.0** source (`StreamableHttpHandler.cs`,
`HttpServerTransportOptions.cs`, `McpEndpointRouteBuilderExtensions.cs` at tag `v2.4.0`).

Already enforced by the SDK on `/mcp`:
- `Accept` must include both `application/json` and `text/event-stream` on POST, else `406`.
- `MCP-Protocol-Version` header validation, else `400`.
- In `Stateless` session mode (the 2.x default and what P2-3 uses): no `Mcp-Session-Id`, the GET and
  DELETE endpoints are **not mapped** at all, legacy `/sse` and `/message` are not mapped, and
  server-to-client requests are disabled. `EnableLegacySse` is obsolete and stays off.
- Session ownership checks (403) apply only in stateful mode, so they do not matter for us.

Not enforced by the SDK (confirmed: the words `Origin`, `AllowedHosts` and a request `Content-Type`
check do not occur in the handler), so P2-6 must add them:
- `Host` validation, `Origin` validation, request `Content-Type` validation.
- Request body size (Kestrel's default is 30 MB), request timeouts (none by default), rate limits,
  concurrency limits.
- Forwarded-header trust, security headers, error-detail suppression, `Server` header removal.

ASP.NET Core provides every one of these as built-in middleware; P2-6 is configuration plus two
small custom middlewares (Origin check, Content-Type check), not a framework.

## 2. Configuration

All optional. Defaults are safe for "behind a reverse proxy on the same host". Names follow the
`NO2SQL_HTTP_*` convention from the parent spec.

| Variable | Default | Meaning |
|---|---|---|
| `NO2SQL_HTTP_ALLOWED_HOSTS` | host of `NO2SQL_PUBLIC_URL` if set; otherwise the hosts in `NO2SQL_HTTP_URLS`, plus `localhost`, `127.0.0.1`, `[::1]`. A wildcard bind (`0.0.0.0`, `[::]`, `*`, `+`) contributes no host, so with neither variable set the default is the three loopback names and the server logs a warning that remote callers get `400` until `NO2SQL_PUBLIC_URL` or this variable is set | Comma-separated `Host` values accepted (`HostFilteringOptions.AllowedHosts`). `*` is refused at startup |
| `NO2SQL_HTTP_ALLOWED_ORIGINS` | origin of `NO2SQL_PUBLIC_URL` if set, plus `http://localhost:<port>`, `http://127.0.0.1:<port>` and `http://[::1]:<port>` for each bound port (a wildcard bind counts as loopback here, with the same warning as above) | Origins accepted when a request carries an `Origin` header |
| `NO2SQL_HTTP_TRUSTED_PROXIES` | empty (forwarded headers ignored) | Comma-separated IPs or CIDRs allowed to set `X-Forwarded-For` and `X-Forwarded-Proto` |
| `NO2SQL_HTTP_MAX_BODY_BYTES` | `1048576` (1 MiB) | Kestrel `MaxRequestBodySize` for `/mcp`; OAuth endpoints are capped at 16 KiB regardless |
| `NO2SQL_HTTP_REQUEST_TIMEOUT_SECONDS` | `120` | Request timeout for `/mcp` (OpenAI's tunnel deadline is 120 s) |
| `NO2SQL_HTTP_RATE_LIMIT_PER_MINUTE` | `60` | Fixed-window limit per bearer token on `/mcp` |
| `NO2SQL_HTTP_RATE_LIMIT_PER_IP_PER_MINUTE` | `300` | Fixed-window ceiling per client IP on `/mcp`, applied before and regardless of the token limit (ChatGPT and claude.ai call from several addresses, so this is generous for one owner and still bounds an attacker on one address) |
| `NO2SQL_HTTP_MAX_CONCURRENT_CALLS` | `16` | Concurrent `/mcp` requests allowed in flight (MongoDB sampling is the expensive part) |
| `NO2SQL_HTTP_MAX_CONNECTIONS` | `256` | Kestrel `MaxConcurrentConnections` |
| `NO2SQL_HTTP_HSTS` | `true` when `NO2SQL_PUBLIC_URL` is `https://`, else `false` | Send `Strict-Transport-Security` on responses whose effective scheme is https |

At startup the server logs one line with the effective values of every setting above (never a
secret), so a misconfiguration is visible in the first screen of logs.

## 3. Middleware, in pipeline order

The order matters; this is the order `Program.cs` must register them.

1. **Forwarded headers** (`UseForwardedHeaders`), only when `NO2SQL_HTTP_TRUSTED_PROXIES` is
   non-empty. `ForwardedHeaders = XForwardedFor | XForwardedProto` (not `XForwardedHost`: the public
   host is configuration, never a header). `KnownProxies`/`KnownNetworks` from the variable, cleared
   of the defaults; `ForwardLimit = 1`. Everything downstream (rate-limit key, HSTS decision, logs)
   uses `HttpContext.Connection.RemoteIpAddress` and `Request.Scheme` as rewritten here.
2. **Host filtering** (`UseHostFiltering` with `AllowedHosts` from section 2, `AllowEmptyHosts =
   false`, `IncludeFailureMessage = false`). Rejects with `400` and an empty body.
3. **Exception handler** (`UseExceptionHandler`) that writes
   `{"jsonrpc":"2.0","error":{"code":-32603,"message":"Internal error. See server logs with error id <id>."},"id":null}`
   with status 500 for `/mcp`, and `{"error":"server_error"}` for OAuth paths, logging the exception
   with the id. `UseDeveloperExceptionPage` is never called, in any environment; the Kestrel option
   `AddServerHeader = false`.
4. **Security headers** (small inline middleware) on every response:
   `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`,
   `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'` (P2-5's HTML pages replace
   this with their own CSP, see the threat model R18), `Cache-Control: no-store` on `/mcp` and every
   OAuth path, `Strict-Transport-Security: max-age=31536000` when `NO2SQL_HTTP_HSTS` is true and the
   effective scheme is https. No `Permissions-Policy` is needed (no browser features are used).
5. **Request timeouts** (`AddRequestTimeouts` + `UseRequestTimeouts`): default policy from
   `NO2SQL_HTTP_REQUEST_TIMEOUT_SECONDS`; `/healthz` gets a 5 s policy. Timed-out requests return
   504 with an empty body.
6. **Origin check** (custom, applied to `/mcp` and all OAuth paths): if an `Origin` header is
   present and its value is not in `NO2SQL_HTTP_ALLOWED_ORIGINS` (exact, case-insensitive scheme and
   host, exact port), or is the literal `null`, respond `403` with an empty body. A missing `Origin`
   is fine (server-to-server clients do not send one). **No CORS headers are ever emitted**; there
   are no browser clients, and `AddCors` is not called.
7. **Content-Type check** (custom): `POST /mcp` must have `Content-Type` with media type
   `application/json` (parameters such as `charset=utf-8` allowed), else `415`. `POST /token` must
   be `application/x-www-form-urlencoded`; `POST /register` must be `application/json`; same `415`.
8. **Rate limiter** (`AddRateLimiter` + `UseRateLimiter`), `RejectionStatusCode = 429`, with a
   `Retry-After` header computed from the window, body
   `{"jsonrpc":"2.0","error":{"code":-32000,"message":"Rate limit exceeded."},"id":null}` on `/mcp`
   and an empty body elsewhere. Policies:
   - `mcp`: a chain of three limiters, all queue limit 0. First, per client IP: fixed window 60 s,
     `NO2SQL_HTTP_RATE_LIMIT_PER_IP_PER_MINUTE` permits. This runs before authentication, so a
     caller who sends a different made-up bearer token on every request is still capped, and a
     refreshed access token starting a fresh token bucket is bounded by it. Second, per token:
     partition key = SHA-256 of the bearer token (first 16 bytes, hex) when an
     `Authorization: Bearer` header is present, else the client IP; fixed window 60 s,
     `NO2SQL_HTTP_RATE_LIMIT_PER_MINUTE` permits. Third, a concurrency limiter of
     `NO2SQL_HTTP_MAX_CONCURRENT_CALLS`.
   - `oauth-token`: per IP, 30 per minute. `oauth-register`: per IP, 10 per hour.
     `oauth-authorize`: per IP, 20 per minute (covers `/authorize`, `/login`, `/consent`).
   - `health`: per IP, 60 per minute.
   The limiter never reads or logs the request body.
9. **Authentication and authorization** (P2-4), then `MapMcp("/mcp").RequireAuthorization()` (or
   the anonymous policy when `--allow-anonymous` was given), the OAuth endpoints (P2-5), and
   `MapGet("/healthz")`.
10. **Fallback**: any other path returns `404` with an empty body. No static files, no default files,
    no directory browsing, no Swagger or OpenAPI, no HTTPS redirection middleware (TLS terminates at
    the proxy), no `UseStatusCodePages` with content.

Kestrel limits set in `ConfigureKestrel`: `MaxRequestBodySize` from `NO2SQL_HTTP_MAX_BODY_BYTES`
(and `[RequestSizeLimit(16384)]` metadata on the OAuth endpoints), `MaxConcurrentConnections` from
`NO2SQL_HTTP_MAX_CONNECTIONS`, `MaxRequestHeadersTotalSize = 16384`, `MaxRequestLineSize = 4096`,
`RequestHeadersTimeout = 15 s`, `KeepAliveTimeout = 130 s`, `MinRequestBodyDataRate` left at the
default (240 bytes/s after 5 s grace), `AddServerHeader = false`.

## 4. Behaviour that must not change

- stdio mode: none of this code runs. `No2SQL` with no arguments is byte-for-byte the 1.1.2 server
  and the strict smoke test proves it in CI.
- `/healthz`: `GET` only, `200` with body `{"status":"ok"}`, no auth, no MongoDB call, no version,
  no configuration values. It is still subject to host filtering and the `health` rate limit.
- Tool behaviour, error messages and `isError` are untouched; this PR adds no code under `Tools/`.

## 5. Acceptance criteria (the PR must show each)

1. `Host: evil.example` on any path returns `400` with an empty body; the configured host returns normally.
2. `Origin: https://evil.example` on `POST /mcp` returns `403`; `Origin: null` returns `403`; no `Origin` passes; the public URL's origin passes. No `Access-Control-*` header appears in any response.
3. `POST /mcp` with `Content-Type: text/plain` returns `415`; `application/json; charset=utf-8` passes.
4. A 2 MiB `POST /mcp` body returns `413`; a 1 MiB body is accepted by the limit (it may still fail JSON-RPC validation).
5. The 61st `POST /mcp` within 60 s from one token returns `429` with `Retry-After`; a different token is not affected; the same token is admitted again in the next window.
6. 17 simultaneous slow `/mcp` requests from one token: the 17th returns `429` immediately.
6a. 301 `POST /mcp` requests within 60 s from one IP, each with a different random bearer token: the 301st returns `429` even though every token is new.
6b. With `NO2SQL_HTTP_URLS=http://0.0.0.0:8787` and neither `NO2SQL_PUBLIC_URL` nor `NO2SQL_HTTP_ALLOWED_HOSTS` set: `Host: localhost:8787` passes, `Host: myserver.example` gets `400`, and the startup log carries the warning.
7. With `NO2SQL_HTTP_TRUSTED_PROXIES` empty, `X-Forwarded-For: 1.2.3.4` does not change the rate-limit partition or the logged client IP; with the test proxy's address configured, it does.
8. A request that triggers an exception in a tool pipeline (test hook or fault injection) returns the generic JSON-RPC body with an error id and no type name, message or stack frame; the id appears in the log with the exception.
9. Every response carries `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and `Content-Security-Policy`; `/mcp` and OAuth responses carry `Cache-Control: no-store`; no response carries a `Server` header; `Strict-Transport-Security` appears only when the effective scheme is https and HSTS is enabled.
10. `GET /mcp` and `DELETE /mcp` return `404` or `405` (whatever ASP.NET routing yields for an unmapped method); `/` and `/anything` return `404` with an empty body.
11. A `/mcp` request that runs longer than the configured timeout (set to 2 s in the test) returns `504`.
12. The startup log line lists every effective hardening value and contains no token, password or connection string.
13. `NO2SQL_HTTP_ALLOWED_HOSTS=*` refuses to start with a message naming the variable.
14. The stdio strict smoke test (`--require-annotations --require-tool-errors --require-discover`) still passes on the same build.

## 6. Notes for Dan

- Use the framework middleware (`Microsoft.AspNetCore.HostFiltering`, `Microsoft.AspNetCore.RateLimiting`,
  `Microsoft.AspNetCore.Http.Timeouts`, `Microsoft.AspNetCore.HttpOverrides`); do not add third-party
  packages for this.
- Keep the two custom middlewares (Origin, Content-Type) as plain `Func<HttpContext, RequestDelegate, Task>`
  lambdas or one small class; they should be under 60 lines together.
- Rate-limit keys derived from a bearer token must hash it first (SHA-256, first 16 bytes) so a raw
  token never sits in a dictionary key or a log line.
- The `Cache-Control: no-store` and the CSP header on OAuth HTML pages will be refined by P2-5; set
  the strict defaults here and let P2-5 override per endpoint.
- Docker: the image binds `0.0.0.0:8787`, so the wildcard default above (loopback hosts plus a
  warning) is what `docker run -p 8787:8787` users get until they set `NO2SQL_PUBLIC_URL`. The
  compose example sets `NO2SQL_PUBLIC_URL`, pins the compose network subnet and puts that CIDR in
  `NO2SQL_HTTP_TRUSTED_PROXIES`, and publishes **only Caddy's** ports, never No2SQL's, so the only
  thing that can reach No2SQL (and set forwarded headers) is on that network. Chiseled images have
  no shell, so there is no Docker `HEALTHCHECK`; orchestrators probe `GET /healthz` from outside,
  and `localhost` passes the host filter for a sidecar probe.
- Coordinate with P2-7 on logging: the request-logging middleware (if any) must redact `Authorization`
  and `Cookie` and never log bodies. Prefer no `UseHttpLogging` at all; the P2-7 audit line per tool
  call is the record.
