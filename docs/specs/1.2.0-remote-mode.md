# Spec: 1.2.0 — remote mode (self-hosted)

Status: approved by Talati on 2026-11-25 (phase 2, "all 11, with built-in sign-in").
Owner: Karen (PM). Release: 1.2.0.

## Goal

Make No2SQL usable from remote-only AI clients (ChatGPT custom connectors, claude.ai web and
mobile custom connectors, the OpenAI Responses API `mcp` tool) by letting users run it as an
HTTP server next to their own MongoDB, with sign-in those clients accept.

## Decisions

- **Self-host only** (Talati, 2026-11-24). Users run No2SQL themselves. A hosted No2SQL service is a
  later phase; nothing here stores anyone's connection string on our side.
- **Built-in sign-in** (Talati, 2026-11-25). No2SQL ships a small single-owner OAuth 2.1
  authorization server (P2-5), so "run it, paste the URL into ChatGPT or claude.ai" works without an
  external identity provider. An external IdP and a static bearer token are also supported (P2-4).
- **stdio stays the default.** `No2SQL` with no arguments behaves exactly as 1.1.2. HTTP mode is
  opt-in with `--http` or `NO2SQL_TRANSPORT=http`.
- **Defaults (Karen):** Streamable HTTP only at `/mcp`, stateless, legacy SSE off; port 8787
  (OpenAI's tunnel-client uses 8080); bind `http://127.0.0.1:8787` unless `NO2SQL_HTTP_URLS` is set;
  env names as in Raj's research (`NO2SQL_TRANSPORT`, `NO2SQL_HTTP_*`, `NO2SQL_OAUTH_*`,
  `NO2SQL_PUBLIC_URL`, `NO2SQL_MONGO_FILE`). One binary for stdio and HTTP; P2-3 measures the size
  increase and we revisit only if it is large.
- **One deployment, one database connection.** `NO2SQL_MONGO` or `NO2SQL_MONGO_FILE`, never in a URL,
  header or tool argument. Per-user connection strings belong to the hosted phase.
- Research and sources: `/mnt/project-files/research/phase2-remote-mode.md` (Raj). Devs read it first.

## Out of scope

- Hosted No2SQL service, multi-tenant accounts, per-user connection strings, a `remotes` entry in
  `server.json`, public directory submissions.
- New tools or changes to SQL / ERD output.

### P2-2 — upgrade ModelContextProtocol 1.2.0 → 2.4.x (Ayush, PR #55)

### P2-3 — HTTP mode (Ayush, `ayush/http-mode`, after P2-2)

1. `--http` or `NO2SQL_TRANSPORT=http` starts an ASP.NET Core host with
   `ModelContextProtocol.AspNetCore`: Streamable HTTP at `/mcp`, stateless, legacy SSE off.
2. Default bind `http://127.0.0.1:8787`; `NO2SQL_HTTP_URLS` overrides. `GET /healthz` returns 200
   without auth and without touching MongoDB.
3. Service registration is shared between stdio and HTTP (one `AddNo2SqlServices()`); only the
   transport block differs. Running with no arguments is byte-for-byte today's stdio server.
4. The same 10 tools, annotations, `isError` and error messages over HTTP.
5. The PR records the size change of the single-file exe and the dnx packages, and aligns
   `Microsoft.Extensions.Hosting` with the SDK's dependencies.
6. MCP Inspector (or the smoke harness) over HTTP: `tools/list` and one `tools/call` shown in the PR.

### P2-4 — authentication, resource-server side (Ayush, `ayush/http-auth`, after P2-3)

1. **Bearer token:** `NO2SQL_HTTP_TOKEN` (at least 32 random bytes) accepted only in the
   `Authorization: Bearer` header, compared in constant time.
2. **External IdP:** `NO2SQL_OAUTH_AUTHORITY` + `NO2SQL_PUBLIC_URL` → JWT validation with audience =
   the public MCP URL, protected resource metadata at the RFC 9728 well-known path, 401 with
   `WWW-Authenticate: Bearer resource_metadata="…"` (and `scope`), 403 `insufficient_scope`.
3. **Refuse to start** in HTTP mode on a non-loopback address unless an auth mode is configured or
   `--allow-anonymous` is passed; anonymous on loopback logs a warning.
4. Works with the Responses API (`server_url` + `authorization`).

### P2-5 — built-in single-owner authorization server (Ayush, `ayush/oauth-server`, after P2-4)

Mark's threat model (`docs/security/1.2.0-p2-5-threat-model.md`, PR #58) is the bar; coding starts once it is merged.

1. OAuth 2.1 authorization server inside No2SQL, enabled with `NO2SQL_OAUTH_BUILTIN=true` and
   `NO2SQL_PUBLIC_URL`: RFC 8414 metadata, authorization code + PKCE S256 only, no implicit, no
   password grant, no `client_credentials`.
2. Client registration: Dynamic Client Registration (RFC 7591) and Client ID Metadata Documents
   (fetched over HTTPS with SSRF protection; advertise `client_id_metadata_document_supported` and
   `token_endpoint_auth_methods_supported: ["none"]`). Pre-registered clients optional.
3. One owner: `NO2SQL_OWNER_PASSWORD` (or a password generated at first start and printed once).
   Login + consent page that shows the client name and its redirect host.
4. Short-lived access tokens with `aud` = public MCP URL; rotating refresh tokens; `offline_access`.
5. Works end to end with ChatGPT (`https://chatgpt.com/connector_platform_oauth_redirect`) and
   claude.ai (`https://claude.ai/api/mcp/auth_callback`) within their 10-second limits.
6. Signing keys and client/refresh-token state persist across restarts in a configurable data
   directory with restrictive file permissions; documented how to rotate and how to revoke all.
7. README security note: what the built-in server protects, and when to use an external IdP instead.

### P2-6 — hardening middleware (Mark specs, Dan implements, `dan/http-hardening`, after P2-3)

Detailed spec: `docs/specs/1.2.0-p2-6-hardening.md` (PR #58). Summary:

1. Host allow-list (`NO2SQL_HTTP_ALLOWED_HOSTS`, default the bound host), reject a present but
   unlisted `Origin` (403), require `Content-Type: application/json` on POST.
2. Rate limit per caller (default 60/min, 429 when exceeded), request body ≤ 1 MiB, request
   timeout 120 s.
3. Forwarded headers honoured only from configured proxies; no exception details in responses;
   standard security headers.
4. Confirm what SDK 2.4 already enforces and fill only the gaps. Defaults documented.

### P2-7 — secrets delivery and redaction (Dan, `dan/http-secrets`, after P2-3)

1. `NO2SQL_MONGO_FILE` (file wins if both are set); trailing newline trimmed.
2. `Authorization`, tokens, owner password and connection string never appear in any log, error body
   or health output; no request-body logging.
3. One audit log line per tool call: tool, database, collection, duration, caller id. No arguments
   that could carry secrets.
4. The leak smoke test is extended to HTTP mode (logs and response bodies).

## Security bar (Mark, review on PR #57)

Every phase 2 PR is reviewed against its acceptance criteria plus these lines. The full bars for
P2-5 and P2-6 are separate documents (PR #58): `docs/security/1.2.0-p2-5-threat-model.md`
(requirements R1 to R30, tests 1 to 19) and `docs/specs/1.2.0-p2-6-hardening.md` (pipeline,
defaults, 14 acceptance criteria). Where they are more specific than this spec, they win.

- **Whole release:** stdio users inherit none of the HTTP attack surface. Every PR shows the strict
  stdio smoke test (`--require-annotations --require-tool-errors --require-discover`) passing, and no
  PR adds a network listener, a file write or an outbound HTTP call to the stdio path.
- **P2-1:** the README says the tunnel forwards `Authorization` but adds no auth of its own, the
  OpenAI org's permissions and API key protect the tunnel, and the connection string stays an env var
  on the owner's machine. No keys in screenshots or logs.
- **P2-3:** loopback by default, non-loopback only through explicit `NO2SQL_HTTP_URLS`; stateless,
  legacy SSE off, no developer exception page, no static files, no HTTPS redirection, no Server
  header; `/healthz` returns only `{"status":"ok"}`; logs to stdout with no secret in any line; the PR
  records the size delta and states that the zips now bundle ASP.NET Core (runtime patches reach zip
  and dnx users only through a new No2SQL release); `ModelContextProtocol.AspNetCore` verified like #55.
- **P2-4:** token ≥ 32 bytes and not a documented example, `FixedTimeEquals`, `Authorization: Bearer`
  only. JWT: exact `iss` and single-string `aud` = public MCP URL, ≤ 60 s skew, `typ` `at+jwt` (or
  `JWT`), asymmetric algorithms only, metadata and JWKS over https only, JWKS refresh rate-limited.
  PRM `resource` = `NO2SQL_PUBLIC_URL` + `/mcp` exactly; 401 and 403 headers as specified, bodies never
  echo the token. Exactly one of built-in AS / external IdP active (static token may coexist);
  anonymous mode warns on every start; auth failures logged with reason and client IP, never the token.
- **P2-5:** the threat model is the bar, in particular R8–R10 (CIMD SSRF guard), R11–R13 (no open
  redirect, PKCE S256, `resource` required, consent page names the verified host), R19–R22
  (single-use hashed codes, rotating refresh tokens with family revocation, ES256 `at+jwt`), R23
  (`revoke-all` rotates the key), R25 (data directory 0700/0600). The PR maps every R-number to code
  or a test and lists anything not covered.
- **P2-6:** the hardening spec is the bar: pipeline order as written, no third-party packages,
  `NO2SQL_HTTP_ALLOWED_HOSTS=*` refuses to start, no CORS headers. SDK 2.4 checks Accept and
  protocol-version headers but not Host, Origin or Content-Type, so these are real gaps.
- **P2-7:** file wins over env var, newline trimmed, warning if the file is group/world-readable;
  log filter drops `Authorization`/`Cookie`/`Set-Cookie` and redacts the connection string, its
  password, `NO2SQL_HTTP_TOKEN` and `NO2SQL_OWNER_PASSWORD` everywhere, including exception text; no
  `UseHttpLogging`; audit line per tool call with caller id (`sub` or token hash prefix); leak smoke
  test also over `/mcp`.
- **P2-8:** non-root, works with a read-only root filesystem (only `/data` writable); chiseled or
  alpine base; MCP name and OCI source/revision labels; `packages: write` only on the publish job,
  actions SHA-pinned, `GITHUB_TOKEN` only, image attested with build provenance; compose example
  uses Caddy, a secret file, the allow-list and auth. No example starts an anonymous server on 0.0.0.0.
- **P2-9:** OCI tag equals the version exactly and is gate-checked against the csproj; same
  `environmentVariables` with `NO2SQL_MONGO` secret; no `remotes` entry.
- **P2-10:** README security note covers, in order: auth mandatory beyond loopback; read-only Mongo
  user and allow-list; what built-in sign-in protects and its residual risks; data directory, backups,
  generated password in container logs, rotate and revoke commands; when to use an external IdP;
  tunnels are for testing; zip/dnx users must update for runtime patches. No real-looking secrets.
- **P2-11:** HTTP smoke test covers the hardening spec's 14 criteria and threat-model tests 1–18;
  test 19 (real ChatGPT and claude.ai, refresh and `revoke-all`) is a release check.
- **Release PR:** CHANGELOG `Security` section says HTTP mode is opt-in and stdio unchanged, names the
  new attack surface and the auth requirement, carries the ASP.NET Core bundling note and Ayush's SDK
  lines from #55.
